# 分布式中央大脑：以 Git 为真源的跨 Agent 记忆架构

本页记录行途多 Agent 协作体系的总体架构（2026-11-03 定性）。一句话：中央大脑不在任何一个 Agent 脑子里，而是长在 Git 上——仓库是脑体，diff 是感知信号，各个 Agent 只是轮流接入的处理器；处理器可换，脑体不换。

## 一、三层结构

| 层 | 载体 | 记录什么 | 回答的问题 |
|---|---|---|---|
| 记忆层 | 全局 changes（跨仓总账，置于 vault 与理念仓） | 个人与 IP 的全局迭代：战略转向、重大决策及其动机 | 为什么走到今天、接下来往哪走 |
| 工程层 | 每仓各自的 CHANGELOG | 该仓的工程迭代：功能、修复、发版 | 这个仓改了什么 |
| 驱动层 | xingtu-cloud-task（私有仓） | 任务卡、认领、状态、回执 | 现在谁去做什么、拿什么回来验 |

三层各记各的，不重复：零件账记不清总账的事，总账也不抄零件账的细节。

## 二、运行机制

1. **记忆共享**：一切判断所需的信息上云进仓，不停留在任何单个 Agent 的私有记忆或会话里。任一 Agent 冷启动接入，先读记忆层即可建立基础判断。
2. **diff 感知**：大脑不重读全量，只感知变化——以基线快照与当前状态作差，只处理漂移与新增。现有巡检体系（每日定时任务巡检拿当日状态与昨日基线作差、只报变化）即此机制的雏形。
3. **动机与 diff 配套**：diff 只显示「变了什么」，不显示「为什么变」。记忆层的每条重大记录必须带动机；只有 diff 没有动机，未来的接手者只能猜测当年意图，等于退回靠会话记忆的老路。
4. **写回闭环**：Agent 干完活必须把结果写回对应层（工程变更入仓 CHANGELOG、决策入全局 changes、任务回执入驱动层），大脑的记忆才持续生长；只读不写的接入不产生资产。

## 三、验收标准（冷启动复述测试）

任何一个新 Agent，在没有任何会话上下文的情况下，只读仓库，应能复述出四件事：

1. 我们是谁、现在在哪（定位与现状）；
2. 为什么走到这一步（关键决策与动机）；
3. 正在进行什么、卡在哪（进行中任务与阻塞）；
4. 接下来谁做什么、验收看什么（待认领任务与验收口径）。

复述不出，就是记忆层还没写够——缺哪补哪，补的位置按第一节分层表对号入座。

## 四、与既有体系的关系

- 云中立是本架构的归属原则：脑体（仓库与文件）归所有者，格式开放，处理器（Agent/工具）可迁徙。
- XSA 是本架构的协作规则：多个处理器并发接入时，靠 Ownership、Lease、Receipt 保证不打架、不重复、不丢回执。
- 本架构不追求再造平台：载体就是现成的 Git 与仓库，规则就是纯文本约定；任何新工具接入，先证明它能读写这三层，再谈替换。
